Timezone is the highest-consequence field on this page. The system is currently set to America/New_York, which is a development default and almost certainly wrong for you. Every arrival time and every late calculation is derived from it. Set incorrectly, every attendance record for every employee will be wrong, and the error is easy to miss because the records still look plausible. Please state your timezone explicitly — for example Asia/Karachi, Asia/Dubai or Europe/London.

How to find the coordinates — 30 seconds per office

  1. Open Google Maps in a browser
  2. Find the office building
  3. Right-click exactly on the building entrance
  4. The first line of the menu shows two numbers, e.g. 24.8607, 67.0011
  5. Click them to copy, then paste into the table above — latitude first, longitude second
Accuracy matters more than it appears. Point at the building itself, not the street or the general area. Phone GPS is typically accurate to 10–30 metres, so a coordinate placed 200 metres away makes any radius check unreliable for everybody at that site.
Important — please read before answering the radius column. The system currently records each employee's location at check-in but does not block a check-in made from outside the office. We verified this in the code: the radius value is stored but no distance check is performed anywhere.

So today the behaviour is "trust, but record" — an employee can check in from home, and their real coordinates are logged for HR to see. Many organisations prefer exactly this, because it supports hybrid and field staff while still giving management full visibility.

If you require check-in to be refused outside the office radius, please tell us — it is additional development, not a setting. See question 7.1.

The grace period is a policy decision, not a technical one, and staff will notice it immediately. With the current 15-minute default, an employee arriving at 09:14 for a 09:00 shift is not marked late. If your policy is stricter or more generous, tell us the number. It is the single setting employees are most likely to query in the first week.
Overnight shifts. If any shift crosses midnight — for example 22:00 to 06:00 — please flag it explicitly. These need confirmation of how the working day is attributed, and should not be assumed.

Please note two real limitations of the current import, so there is no surprise later.
  1. Only these five columns are imported. Office, department, job title, hire date, gender and work mode are not read from the file even if you include them — they must be assigned afterwards, employee by employee, through the admin screens. For a large workforce that is a meaningful amount of manual work, and it should be planned for. If you would prefer these to import as well, it is a small development change and we would recommend making it before you import hundreds of records.
  2. The file must be CSV, not Excel. An .xlsx file will be rejected. In Excel choose Save As → CSV (Comma delimited).

7.1  Should check-in be blocked outside the office? Affects scope

OptionBehaviourStatus

Option A suits hybrid and field staff and still deters false check-ins, because employees know their true position is recorded. Option B suits fixed-site workforces — but be aware it will reject genuine staff when GPS drifts indoors, so a manual override for HR becomes necessary alongside it.

9 HR and legal Blocker

9.1  Employee privacy notice

Because this system records physical location, employees must be told before collection begins. We can supply the factual content; the document itself must be issued by you.

What the notice must stateThe accurate answer for this system
What is collectedName, employee code, department, check-in and check-out times, GPS coordinates at those two moments only, and the network (IP) address used
What is not collectedNo continuous tracking. Location is captured only when the employee presses check in or check out — never between, and never in the background
WhyVerifying attendance and calculating working hours
Who can see itAdmin and HR users only
How long it is keptyour retention period — please specify
The second row is the one that resolves most staff objections. Employees generally assume a location feature means continuous tracking. Stating plainly that position is captured only at the two moments they press a button — and never in between — addresses the concern before it spreads. It is also simply true of this system.
