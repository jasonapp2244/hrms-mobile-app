2 What must be provided — the actual blockers

Nothing below is development work. Each is an account or a purchase, and the system cannot go live without them.

# Item Why it is needed Indicative cost Provided by
1 Domain name Staff need an address to sign in at, and a certificate can only be issued for a real domain. A privacy-policy link that points at a local machine is also of no use to anyone. ~$10–15 / year Client
2 Hosting (managed webspace) Runs the application, the database and the background jobs. Managed webspace has been chosen over a VPS, so the reminders, auto-close, nightly backups and scheduled reports are driven by the hosting panel's scheduled tasks rather than by a process that runs continuously. See the note below the table. ~$4–10 / month Client
3 HTTPS certificate Attendance records include names and locations. Free and renewed automatically, issued from the hosting control panel rather than bought — but it has to be switched on for the subdomain before staff can sign in. Free Us
4 Email sending account Currently the one functional gap. Password resets, leave decisions, scheduled reports and document-expiry warnings are all built and tested, and all go nowhere until a real mail account is connected. Any SMTP provider works. Free–$15 / month Client

Costs are indicative market rates as of August 2026 and are not quotes — the exact figures depend on the provider and plan you choose.

What managed webspace costs you, in behaviour rather than money. Every feature works and nothing is switched off, but two things are weaker than on a VPS. A notification — a leave decision, a password reset — goes out within about five minutes instead of within a second, because the hosting panel will not run a task more often than that. And the nightly backup is still taken, but it can no longer be automatically test-restored to prove it reads back, because that needs a spare database the plan does not provide; the dumps should therefore be restored by hand once before go-live and periodically after. Moving to a VPS later reverses both, and is a change of host rather than a change of software.

Minimum to go live: items 2 and 4 — the webspace and an email account. Item 1, the domain, is done: emp.klutchcleaning.com exists and already points at the webspace. Item 3, the certificate, is free and switched on by us from the panel.

4 What happens on deployment day

Every step below is already scripted and has been rehearsed. None of it is written on the day.

#StepWhat it does
1Hosting preparation Confirm the PHP version and its extensions, and point the subdomain at the application's public folder — never at the folder above it, which would publish the configuration file.
2Database and code Create the database, deploy the application, build the schema.
3Domain and HTTPS Switch on the certificate for emp.klutchcleaning.com, which already resolves. From here the site is reachable at your own address, over an encrypted connection.
4Email Connect the mail account and send a live test.
5Background jobs Add the two scheduled tasks that run the reminders, the end-of-day close, the nightly backup and the scheduled reports. On this hosting they fire every five minutes rather than continuously.
6Company setup Create the company and the first administrator, set the timezone and the working week, and import the employee list if one is supplied.
7Pre-flight check An automated audit refuses the go-live if anything is unsafe — debug mode left on, email not really sending, the test sign-in panel still enabled, default passwords, a missing backup, or a wrong timezone.
8Handover Walk through the dashboard, confirm a real check-in, and hand over the administrator account.
Backups are set up on day one and verified rather than assumed — each nightly dump is restored into a scratch database to prove it reads back before the old one is rotated away. Uploaded documents and photos are backed up alongside the database; a restored database without its files would be a list of documents that all fail to open.

5 Deliberately not included

Stated plainly so there is no surprise later. None of these blocks the system going live, and each can be added afterwards.

ItemPosition
AI HR assistant Out of scope by agreement. It was designed to sit on top of mature attendance and leave data, and that data now exists — so it remains available as a later phase whenever you want it.
Multi-company tenancy The system runs one company. Every record is already company-scoped internally, so supporting several is a later addition rather than a rebuild.
Conditional policy rules The policies themselves are all configurable — working week, reminder and auto-close windows, geofencing, two-factor requirement, idle timeout. What does not exist is an if-this-then-that rule builder on top of them.
Drag-and-drop roster The roster planner is a grid you fill in, with draft and publish. It works; the dragging is cosmetic and was not built.
