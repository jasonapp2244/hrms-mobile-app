Critical path

What is actually holding up launch

None of these is a coding task. All three are accounts, credentials or hosting that only the business can provide.

1
Blocks everything below

No production server yet

A phone cannot reach a laptop, push services will not call one back, and neither app store accepts a privacy-policy address pointing at a developer machine. Store submission, push notifications and real-device testing all wait on this single item.

The work itself is done: deployment scripts, web-server and background-worker configuration, the scheduled-task line, the environment template and an automated pre-flight check that refuses to deploy an unsafe configuration.

2
Configuration only

Outgoing email is not connected

Password resets, leave decisions, scheduled reports and document-expiry warnings are all built and tested. They currently write to a log file instead of sending. Supplying mail-server credentials switches them on — there is no code left to write.

3
Console work

Push notifications are silent

Both halves are built: the phone registers for notifications at sign-in and opens the right screen when one is tapped, and the server sends them. It stays silent until a Firebase project exists. The app runs normally in the meantime rather than failing.

Next step

What we need from you to go live

Four items. The first unblocks the other three and everything in the critical path above.

Hosting & domain Web hosting plus the address the system will live at. The deployment is planned for emp.klutchcleaning.com.
Mail credentials An outgoing mail account so the system can send resets, approvals and reports.
Firebase project A free Google account for push notifications to staff phones.
Store accounts Apple Developer and Google Play publisher accounts, needed to list the staff app.
