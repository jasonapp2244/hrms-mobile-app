1 Overview & Purpose

A cross-platform Employment Management Portal solution that lets organizations manage employees, attendance, departments, schedules, leave, and HR reporting from one centralized platform — with QR-based attendance and an AI-powered HR assistant.

Delivery Approach

The build starts with a web-based Admin Dashboard (Laravel + MySQL) focused on the Attendance module. This front-loads the database, backend, and API that the future Android/iOS apps reuse — no rewrite. Mobile apps and advanced modules follow in later phases.

Centralized platform QR-based attendance Role-based access HR reporting AI HR assistant Android & iOS (future)

2 User Roles & RBAC

The system supports three roles with permission-based access, implemented with the Spatie laravel-permission package (roles ↔ permissions ↔ users).

RoleDescriptionPhase 1 Status
Company AdministratorFull control — company setup, employees, attendance, reports, configuration.Active P1
Human Resources (HR)HR operations — employees, attendance, leave, reports (no company-level config).Structured now, login later
EmployeeSelf-service — profile, clock in/out, attendance history, schedules, leave requests.Mobile phase

Permission Model

Granular permissions are seeded and assigned per role. Admin receives all; HR receives an HR subset (seeded, login-disabled in Phase 1); Employee is reserved for the mobile phase.

manage-employees manage-departments view-attendance configure-qr export-reports manage-leave manage-company 
@can('export-reports') ... @endcan          // Blade
$this->authorize('manage-employees');        // Controller
Route::middleware('permission:view-attendance') // Route
Enabling HR later = flip the login gate + confirm HR's permission set. No schema change, no refactor.

6 Attendance Management P1 — Primary Focus

The core of Phase 1. QR-based clock in/out with dynamic rotating codes, server-side validation, logging, scoring, and summaries.

FeatureRequirement
QR Clock InEmployee scans office QR to record start of work.
QR Clock OutEmployee scans office QR to record end of work.
Dynamic rotating QROffice QR encodes a short-lived token, rotating every ~15–30s.
QR validationServer checks token freshness, office match & employee assignment.
Office-specific QREach office/branch produces its own independent QR stream.
Timestamp recordingServer-side timestamp for every event (device clock not trusted).
Attendance logsFull event table: employee, office, type, timestamp, status.
Attendance scoringPer-employee score: on-time %, late count, absences.
Attendance summariesDaily / weekly / monthly rollups per employee & department.
Attendance historyFilterable, paginated history in the dashboard.

7 QR Check-In / Check-Out Design P1

Confirmed model — A: Office displays rotating QR → employee scans. Delivered in Phase 1 without a native app via a web kiosk + PWA scanner.

🖥️ Web Kiosk

  • Browser screen on a tablet/monitor at the office entrance
  • Displays the dynamic rotating QR (refresh ~15–30s)
  • Built into the admin dashboard — no special hardware

📷 PWA Scanner

  • Mobile web page — camera in the browser (getUserMedia + jsQR)
  • No app install required
  • Same API endpoint the native apps will call in Phase 2

Validation Flow

  1. Each office has a secret. Server computes token = HMAC(office_secret, time_window).
  2. Kiosk shows a QR encoding {office_id, token}, refreshing every ~15–30s.
  3. Employee scans → PWA sends {employee_id, office_id, token} to the API.
  4. Server recomputes the valid token for current + previous window and compares.
  5. Valid → record clock event with server timestamp. Invalid/expired → reject.
Anti-cheat: rotation blocks screenshot-and-clock-in-from-home. Optional geolocation binding can be added later for stricter enforcement.
