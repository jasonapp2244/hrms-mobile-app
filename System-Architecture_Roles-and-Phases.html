2Role Architecture

Three roles exist in the system today. A fourth — Manager — is proposed for the phase that introduces approval workflows.

🔴 Admin

Business owner / system owner. Full control of configuration and data.
16 / 16 permissions
  • everything
  • manage-company
  • manage-offices
  • manage-roles
  • manage-settings
  • manage-shifts

🟠 HR

Day-to-day people operations. Runs employees, attendance and reporting.
10 / 16 permissions
  • view-dashboard
  • manage-employees
  • import-employees
  • manage-departments
  • manage-designations
  • view / manage-attendance
  • view / export-reports
  • manage-leave (reserved)
  • manage-shifts
  • manage-company
  • manage-offices
  • manage-roles
  • manage-settings

🔵 Employee

Locked-down self-service. Can reach nothing else in the application.
1 / 16 permissions
  • view-attendance (own only)
  • all admin modules
  • all company data
  • other employees' records

⚪ Manager proposed

Team lead. Approves their own team's requests without seeing company-wide data.
— not yet created
  • approve-leave (team)
  • view team attendance
  • approve regularisation
  • view team roster
Worth a decision: HR cannot manage shifts HR is not granted manage-shifts, so the Shifts & Roster menu is hidden for HR users and the route returns 403. Setting work schedules is normally an HR function, so this looks like an oversight rather than a policy. It is a one-line change in the seeder — but it is your call, so it has not been changed.
Housekeeping configure-qr is still seeded as a permission but the QR feature was removed on 2026-07-20. It grants access to nothing and should be dropped in a cleanup pass.

Two client decisions redefine this entire map 1. Is Leave Management required? → determines Phase 4 (9 features) and whether the Manager role is ever created.
2. Is the mobile app in scope — Android only, or Android + iOS? → determines Phases 3, 6 and 7 (54 features, roughly half the remaining product).
Until both are answered, Phases 3–7 cannot be priced or scheduled with any confidence.
Before any real launch The system currently runs on seeded demo data. Real offices, departments, shifts and employees must be loaded, HTTPS must be enabled (browser GPS silently stops recording on insecure origins), and a database backup routine must exist before live employee records are entered.
