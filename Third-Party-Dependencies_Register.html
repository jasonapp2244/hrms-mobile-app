1 Executive summary

The short answer for management: this system is unusually light on third-party commitments. It depends on no paid service, no external API, and no vendor account in its current form. The one purchased item is a design template, covered in §12.3.

The 133 figure sounds large and always alarms non-technical readers, so it is worth explaining once: the team chose 8 libraries. Those 8 libraries each depend on others, which depend on others again. All 133 arrive automatically from a single command and are pinned to exact versions in a lock file, so every environment installs an identical set. This is normal and is how every modern PHP, Java, .NET or JavaScript project works.

Why this matters commercially. There is no vendor who can raise a price, change terms, or withdraw a service and thereby break this application. Everything it needs is either open-source code held in our own repository or a server we control. Should the organisation ever need to run the system on an isolated internal network with no internet access at all, one small change (§9) is the only obstacle.
Two things do need a decision. A web font is being fetched from Google on every page load (§9.2); and the admin interface is built on a purchased commercial template whose licence must be confirmed as held by the company (§12.3). The third — an unused QR library — was resolved on 6 August 2026 and is recorded as closed at §13.1.

9 Live external services the running system contacts

This is the section most people actually mean when they ask about third-party dependencies: what does the application talk to over the internet while it is running?

9.1  Browser Geolocation API

AspectDetail
ProviderNone — it is built into every modern browser.
Used forCapturing employee latitude and longitude at check-in and check-out.
CostFree. No account, no key, no quota.
ConditionRequires HTTPS. Browsers refuse location access over plain HTTP, so an SSL certificate is a functional requirement, not merely good practice.
Data leaving usNone. The browser gives the coordinates to our own page, which sends them to our own server.

9.2  Google Fonts Needs a decision

AspectDetail
What happensThe template stylesheet contains two @import lines pulling the Roboto and Archivo typefaces from fonts.googleapis.com on every page load.
CostFree, no account required.
Concern 1 — availabilityThis is the only reason the system cannot run on an isolated internal network. Without internet access, pages still work but fall back to a default typeface.
Concern 2 — privacyEach page load sends the employee's IP address to Google. German courts have ruled this a GDPR breach when done without consent. Whether that applies here depends on our jurisdiction.
FixDownload both typefaces and serve them from our own server. Roughly half a day of work. Removes both concerns permanently and slightly improves page speed.

9.3  Google Maps — link only, not an API

Attendance records with coordinates display a "view on map" link pointing at google.com/maps. This is an ordinary hyperlink that opens in a new tab.

This is worth stating plainly because it is easily misread. There is no Google Maps API key, no billing account, no usage quota and no cost. The application never calls Google's servers for this. An embedded map displayed inside our own pages would require a key and a billing account — but that is a future enhancement, not a current dependency.
Complete answer to the question: the running system makes exactly one outbound network request to a third party — the Google Fonts stylesheet. Nothing else. No analytics, no tracking, no error-reporting service, no content delivery network, no external API of any kind.

12.2  The LGPL packages

The PDF engine (dompdf and two font libraries) and the HTML sanitiser are LGPL. LGPL permits unrestricted use — including in closed, commercial software — provided the library itself is not modified and redistributed. We use them unmodified, exactly as published. No source-disclosure obligation attaches to our application code.

12.3  The one item requiring confirmation Action

The SmartHR administrative template is commercial software. Unlike everything else in this register, it was purchased rather than freely licensed, and it is typically sold per-application under a marketplace licence.

Two questions need answering before delivery, and neither is technical:
  1. Does the company hold a valid purchase licence for this template, and is the licence key on file?
  2. Is it the correct licence tier? Marketplace templates are usually sold under a "regular" licence covering one end product where users are not charged, and an "extended" licence where they are. If this system is ever sold or offered as a paid service to other organisations, the extended licence applies.
This is inexpensive to resolve now and awkward to resolve after a client deployment.
Everything else is clear. Setting the template aside, there is no licence in this project that restricts commercial use, requires publishing our source code, or carries a recurring fee.
